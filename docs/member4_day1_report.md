# Member 4 — Day 1 Final Report (Schedule & Time Analytics)

## 1. Dataset & Scope
- **Dataset Used**: `data/processed/paimana_master_v1.csv` (1,775 projects).
- **Time Fields Available**: `approval_date`, `original_completion_date`, `revised_completion_date`.
- **Derived Time Metrics**: `original_duration_months`, `time_overrun_months`, `time_overrun_flag`.

## 2. Schedule Analysis Summary
- **Projects with a Schedule Extension**: 1,110 (62.5%)
- **Projects Strictly on Time**: 665 (37.5%)
- **Mean Time Overrun (for delayed projects)**: 30.23 months
- **Median Time Overrun (for delayed projects)**: 22.96 months
- **Maximum Time Overrun**: 299.96 months (~25 years)

*Important Pattern*: Time overruns (62.5%) are far more prevalent than cost overruns (27.2%). Delays are heavily localized to specific agencies and states, and massive initial planned durations strongly correlate with severe eventual delays.

## 3. Recommended ML Target
- **Selected Target**: `time_overrun_flag` (Binary Classification: `1` if revised > original, else `0`).
- **Alternative**: `time_overrun_months` (Regression). Rejected for the initial Day-2 model due to extreme right-tail outliers (delays of 20+ years) which will skew loss functions. We will first build a robust binary risk classifier.

## 4. Prediction Point Recommendation
- **Selected Strategy**: **Implementation-time Early Warning**.
- We will predict the delay risk using the current state of the project (e.g., Progress at month $X$). This is more useful for active monitoring than Approval-time prediction.

## 5. ML Feature & Leakage Analysis
- **Safe Inputs**: `original_duration_months`, `original_cost`, `state`, `agency`.
- **Snapshot Inputs**: `physical_progress`, `cumulative_expenditure` (Valid because we are predicting at Implementation-time).
- **LEAKAGE VARIABLES (DO NOT USE)**: 
  - `revised_completion_date` (Mathematically defines the target).
  - `time_overrun_months`, `time_overrun_flag` (They ARE the target).

## 6. Temporal-Data Limitations
The current July 2026 data is a **single monthly snapshot**. 
Because we lack a historical time-series (e.g., tracking a single project's progress month-over-month), our model will perform *retrospective pattern recognition* rather than true velocity-based forecasting. Robust predictive forecasting requires historical PAIMANA/OCMS datasets to be appended.

## 7. External Data Sources Researched (Additional Variables)
- **PARIVESH (MoEFCC)**: Forest and Environmental clearance status (Major cause of pre-construction stalling).
- **State Land Records**: Land acquisition completion %.
- **IMD Data**: Heavy monsoon rainfall inherently delays civil construction.

## 8. Recommended Day-2 Models & Explainability
- **Primary Model**: Random Forest Classifier or XGBoost Classifier.
- **Evaluation Metrics**: 
  - **F1-Score** (Primary balance).
  - **ROC-AUC** (To evaluate risk ranking).
  - **Recall** (High recall is desired to catch delays early).
- **Explainability**: **SHAP** will be integrated to output human-readable reasons (e.g., "High Risk because Progress is only 15% but 60% of Original Duration has elapsed, and Agency is historically slow").

## 9. Dashboard Requirements (For Member 6)

- **Charts to include**:
  - Time Overrun Distribution.
  - Progress vs Original Duration scatterplot (helps visually spot stalling projects).
- **Filters needed**: Agency, State.
